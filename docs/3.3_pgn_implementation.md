# Subtask 3.3 — PGN support: implementation notes

> Status: **implemented and tested.** This is the build record for subtask 3.3,
> following the design agreed in [3.3_pgn_discussion.md](3.3_pgn_discussion.md)
> and [3.3_pgn_discussion_round2.md](3.3_pgn_discussion_round2.md). Subtasks 3.1
> (board/pieces) and 3.2 (FEN) continue to work unchanged.

## What was built

A pure-Typst rules engine plus a PGN pipeline, in the layered shape we designed.
Each layer sits behind a narrow interface so later layers never reach past the
one below them.

| Module | Role | Key exports |
|---|---|---|
| `src/engine.typ` | Two-stage legal move generation + state transition | `is-square-attacked`, `legal-moves`, `apply`, `in-check` |
| `src/san.typ` | SAN parsing + resolution against legal moves | `san-to-move`, `play-san` |
| `src/pgn.typ` | Tokenizer + recursive movetext/variation tree (Phase A) | `parse-pgn` |
| `src/game.typ` | Navigation (Phase B, engine on demand) | `mainline`, `position-after`, `board-after`, `line`, `game-result`, `game-start` |
| `src/style.typ` | `diagram-style` dict + document defaults | `default-style`, `set-chess-defaults`, `chess-style` |
| `src/board.typ` | Renderer (now style-driven) + orientation + highlights | `render-board` |
| `lib.typ` | Public API surface + `#figure` wrapper | `chess-diagram`, `board-after`, `parse-pgn`, … |

## Design decisions, as realised

### Move generator: two stages

As agreed, generation is split:

1. `_pseudo-moves` + `_castling-moves` produce candidates respecting piece
   geometry, blockers, captures, and the en-passant / castling preconditions —
   **without** checking whether the mover's own king is left in check.
2. `legal-moves` filters them: `apply` each candidate, then test whether the
   mover's king `is-square-attacked`.

`is-square-attacked(board, col, row, by)` is the keystone primitive, reused for
king safety (stage 2), check detection, castling through/into check, and
mate/stalemate (no legal moves + king attacked ⇒ mate). Castling is fully
validated in generation (rights, empty squares, and the three king squares not
attacked), so the generic filter is merely a backstop for it.

`apply` is pure (no mutation of its input) and handles captures, en passant
(captured pawn off the destination square), castling (rook moves too),
promotion, castling-rights updates (king/rook moves, and a rook captured on its
home square), the en-passant target, the halfmove clock, and the fullmove
counter.

### SAN needs full legality

`san-to-move` resolves a SAN token by matching it to exactly one of the
position's **legal** moves. Zero matches ⇒ illegal/unresolvable (hard error);
more than one ⇒ ambiguous (hard error). This is precisely why a full legal
generator is required: SAN omits disambiguation when only one candidate is
legal (e.g. the other is pinned), so resolving it correctly needs pin/king
safety, not just pseudo-legal geometry.

SAN is parsed by stripping trailing `+ # ! ?`, peeling a promotion `=Q`, taking
the trailing two characters as the destination square, then reading an optional
piece letter, from-file, from-rank and `x` from the prefix. (Manual parsing,
not one big regex, to avoid capture-group ambiguity on tokens like `e4`.)

### Lazy two-phase parsing

`parse-pgn` returns an **array of games** (a file may hold many) and does only
Phase A: tokenize, read the tag dict, and build the movetext **tree** with
`san` strings. The engine (Phase B) runs only when a position is requested via
`position-after` / `board-after`. So a tournament file read only for
`game.result` never invokes the engine — the performance win we banked from the
round-2 discussion.

### Structures: game data vs presentation

* A `game` is `(tags, movetext, result)`; a move node is
  `(san, nags, comment-before, comment-after, variations)`. `variations` is the
  recursive RAV tree (an array of alternative sub-lines that branch *before*
  the node they hang on).
* `diagram-style` is a separate plain dict (size, colors, labels + sides,
  orientation, highlight, piece fills/font, …). Resolution merges three layers,
  later wins: **built-in defaults ⊕ document defaults (state) ⊕ per-call
  overrides** — so `set-chess-defaults(...)` styles everything after it while a
  single diagram can still override.

### Locators (mainline and nested variations)

* `"30w"` / `"30b"` → after White's / Black's 30th move on the mainline.
* A path dict for variations, e.g.
  `(line: ((at: "2w", into: 0), (at: "2b", into: 0)), at: "3w")` — descend into
  variation 0 at White's move 2, then variation 0 at Black's move 2, then take
  the position after White's move 3. Ply numbering: White's move *m* → ply
  *2m−1*; Black's → *2m*.

### Variations without altering external PGNs

* RAVs already in the file are navigated by the path locator above — the parsed
  game is immutable; we just walk a different branch.
* `line(start, moves)` explores a *new* line: it applies SAN moves from a
  position (or FEN) and returns `(start, after 1, after 2, …)`. The source is
  never mutated.

### Renderer refactor (consequence of `diagram-style`)

`render-board` now resolves a style and reads fields from it; the old
per-argument names (`size`, `light`, `dark`, `labels`, `file-side`,
`rank-side`, …) survive as style overrides, so 3.1/3.2 callers are unchanged.
One `_screen(col, row, sq, orientation)` function maps every square, piece,
highlight and label, so board flipping (Black at the bottom) is a single branch.

### Errors

Hard errors on malformed PGN (better than a silently wrong diagram): broken tag
syntax, unterminated tags/comments and stray variation parens fail at parse
time; illegal, ambiguous or unparseable moves fail when navigated. Missing
Seven-Tag-Roster tags are tolerated and default.

### No `read-pgn` wrapper

Deliberately omitted. Typst's `read` resolves paths relative to the file the
call appears in, so a library wrapper would resolve relative to the package, not
the user's document. The documented idiom is `parse-pgn(read("game.pgn"))` in
the user's own file.

## Tests

Run all with `bash tests/run.sh` (pass-cases must compile; fail-cases must error
and emit their `// EXPECT:` substring).

* `tests/unit.typ` — coords, FEN, engine (start = 20 moves, perft(2) = 400,
  Kiwipete = 48, scholar's-mate detection), SAN (replay, castling,
  disambiguation, promotion-with-capture, en passant), PGN (tags, comments,
  NAGs, multi-game, raw), nested variations, navigation, and the full **Opera
  Game** ending in detected checkmate (read from `tests/opera.pgn`).
* `tests/real.typ` — full replay of **Spassky–Fischer, WCh 1972 game 5** in both
  plain and Stockfish-annotated forms (`examples/pgn/`).
* `tests/api.typ` — exercises every public `lib.typ` export; renders to PNG.
* `tests/fail/` — six must-error cases: malformed roster, unterminated tag,
  stray paren, illegal move, garbage SAN, ambiguous SAN.

Result at completion: **12 pass-cases compile, 6 fail-cases error correctly.**

## Two real bugs the tests caught

1. **An illegal test variation.** A hand-written `2. Bc4 … 3. Ng5` line had no
   knight on f3, so `Ng5` was genuinely illegal — the lazy engine rejected it
   when navigated. The test data was wrong, not the engine; confirming the
   engine refuses illegal SAN.
2. **CRLF grapheme clustering.** Unicode segmentation groups `\r\n` into a single
   `.clusters()` element, which the whitespace check missed, so a CRLF file
   (the annotated Spassky–Fischer game) tokenized to garbage. Fixed by
   normalising line endings (`\r\n`/`\r` → `\n`) at the top of the tokenizer;
   now guarded by `tests/real.typ`.

## Build order used

`is-square-attacked` → pseudo-legal generator → legality filter → `apply` →
SAN resolver → PGN tokenizer/parser → navigation/locators → style refactor →
public API → tests. Each layer was perft/SAN/round-trip checked before the next
was built on top.
