Amending Creation of Positions
==============================

We have several methods now to create a
position and we also have methods to apply 
new moves to an existing position within our
PGN / "game" API

Correct me, if I'm wrong, but I think we have
"#board-after" for applying a locator or a "path"
to a board at a certain move within a game.


What we don't have is applying a move text
to a position and creating a new position, correct?

I thought about something along the lines
#position(<FEN>, <MOVE_LIST_AS_TEXT>).

E.g. after the first two moves of the RUy Lopez
we have this FEN: r1bqkbnr/pppp1ppp/2n5/4p3/4P3/5N2/PPPP1PPP/RNBQKB1R w KQkq - 2 3 

Then we play "Bb5 a6 Ba4 Nf6" and get this new position (FEN:
r1bqkb1r/1ppp1ppp/p1n2n2/4p3/B3P3/5N2/PPPP1PPP/RNBQK2R w KQkq - 2 5)

suitable for rendering.

If <FEN> is empty / none, we assume the standard starting 
position. We could use this also in #board-after, instead of a 
"path" we would analyze the move text.

The condition would be that we can take the move text and 
can resolve it to a list of legal moves. This would involve
in both cases the use of the engine.

Please discuss!
